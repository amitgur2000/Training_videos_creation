# Chapter registry

The living index of user-education chapters. The skill reads it to resolve a chapter name, appends rows for new chapters, and updates the language status after every run.

## Rules

- **Each chapter is a folder, `docs/user_education/<NN>_<slug>/`,** holding one `<NN>_<slug>.record.py` and a folder per language (`he/`, `en/`, ...) with the script and both devices' videos. The number is two digits, and is the chapter's place in the curriculum.
- **New chapters get the next free number** unless the user picks one. Existing numbers and folders are never renumbered.
- **Start page:** `/dashboard`, where the app lands after login, unless the chapter is about something before login. A run's description can override it.
- **Status per language:** `drafted` (the script is written), `produced` (both videos made), `verified` (the user watched them and signed off).

## Notes per chapter

- **01 How to add a new patient**
  - User's brief (2026-10-04): open a new patient and go over the fields. Emphasize three things:
    - the therapeutic approach: summaries are generated by it, and it can be changed at any time, effective from the next meeting
    - recording consent: ask first, record only after. Without recording, a meeting can still be created by typing notes, recording yourself, or uploading an external transcript.
    - automatic session end: for when you forget to stop the recording
  - Decisions (2026-10-04):
    - Show the consent-blocking dialog by pressing record on a patient without consent, then close it. No real recording.
    - "Recording yourself" covers both the dictation mic in typed notes and uploading your own audio file.
  - Fixture: each run creates one fictional patient on the staging demo account. It cannot be deleted; the user accepted leaving it.
